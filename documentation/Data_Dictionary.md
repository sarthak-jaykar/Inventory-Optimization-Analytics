# Data Dictionary

> All data is **fictional and synthetic**, generated by `python/generate_data.py` with a fixed random seed (`20260105`). Currency is INR; all quantities are in pieces (`pcs`).

## 1. Model overview

```
dim_item ──┐
           ├─► dim_item_location ─┬─► fact_inventory_weekly ◄── dim_date
dim_warehouse ┘                   └─► fact_replenishment_orders ──► fact_order_receipts
```

| Table | Grain | Primary key | Rows |
| --- | --- | --- | --- |
| `dim_item` | One row per item | `item_id` | 40 |
| `dim_warehouse` | One row per warehouse | `warehouse_id` | 3 |
| `dim_item_location` | One row per item × warehouse | `item_location_key` | 90 |
| `fact_inventory_weekly` | One row per item-location per week | (`item_location_key`, `week_start_date`) | 2,340 |
| `fact_replenishment_orders` | One row per replenishment order | `order_id` | 661 |
| `fact_order_receipts` | One row per delivery against an order | `receipt_id` | 649 |
| `dim_date` (Power BI) | One row per day | `Date` | 183 |

Total transaction records (weekly + orders + receipts): **3,650**.

### Relationships (Power BI)

| From (one) | To (many) | Active |
| --- | --- | --- |
| `dim_item[item_id]` | `dim_item_location[item_id]` | Yes |
| `dim_warehouse[warehouse_id]` | `dim_item_location[warehouse_id]` | Yes |
| `dim_item_location[item_location_key]` | `fact_inventory_weekly[item_location_key]` | Yes |
| `dim_item_location[item_location_key]` | `fact_replenishment_orders[item_location_key]` | Yes |
| `fact_replenishment_orders[order_id]` | `fact_order_receipts[order_id]` | Yes |
| `dim_date[Date]` | `fact_inventory_weekly[week_start_date]` | Yes |
| `dim_date[Date]` | `fact_replenishment_orders[order_date]` | No (used via `USERELATIONSHIP`) |
| `dim_date[Date]` | `fact_order_receipts[receipt_date]` | No |

All relationships are one-to-many with single-direction filtering. Two inactive date relationships avoid a second filter path to the same data.

## 2. Source tables (CSV, `data/raw/`)

### `dim_item`
| Column | Type | Description |
| --- | --- | --- |
| `item_id` | Text | Item identifier (`RM001`–`RM024` raw materials; `FG001`–`FG016` finished goods) |
| `item_name` | Text | Item name |
| `item_type` | Text | `RM` (raw material) or `FG` (finished good) |
| `category` | Text | Item category (for example Semiconductors, PCBs, LED Drivers) |
| `uom` | Text | Unit of measure; `pcs` for all items |
| `unit_cost` | Decimal | Standard unit cost (INR) |
| `abc_class` | Text | `A`, `B` or `C` value class |
| `criticality` | Text | `Critical` or `Standard` |

### `dim_warehouse`
| Column | Type | Description |
| --- | --- | --- |
| `warehouse_id` | Text | `PUN`, `CHE` or `GUR` |
| `warehouse_name` | Text | Warehouse name |
| `city` | Text | City |
| `region` | Text | West, South or North |
| `warehouse_role` | Text | `Main plant` or `Regional` |

### `dim_item_location`
Holds the item-warehouse policy settings and the **current ERP settings**.

| Column | Type | Description |
| --- | --- | --- |
| `item_location_key` | Text | `item_id\|warehouse_id` (for example `RM001\|PUN`) |
| `item_id` | Text | Foreign key to `dim_item` |
| `warehouse_id` | Text | Foreign key to `dim_warehouse` |
| `planned_lead_time_days` | Integer | Planned replenishment lead time |
| `safety_stock_days` | Integer | **Policy:** days of average demand held as safety stock (Critical = 14, Standard = 7) |
| `order_cycle_days` | Integer | **Policy:** days of demand covered by one replenishment (ABC: A = 14, B = 21, C = 28) |
| `max_cover_days` | Integer | **Policy:** maximum cover; `round-half-up(1.5 × (safety_stock_days + order_cycle_days))` |
| `erp_reorder_point_qty` | Integer | **Observed:** current static reorder point in the (fictional) ERP |
| `erp_order_qty` | Integer | **Observed:** current fixed order quantity in the (fictional) ERP |

### `fact_inventory_weekly`
Weekly snapshot and flow per item-location. Weeks run Monday–Sunday.

| Column | Type | Description |
| --- | --- | --- |
| `item_location_key` | Text | Foreign key to `dim_item_location` |
| `week_start_date` | Date | Monday of the week (26 weeks: 5 Jan – 29 Jun 2026) |
| `opening_stock` | Integer | **Snapshot:** stock at the start of the week |
| `receipts_qty` | Integer | **Flow:** sum of order receipts dated in the week |
| `demand_qty` | Integer | **Flow:** requested quantity |
| `fulfilled_qty` | Integer | **Flow:** `min(demand_qty, opening_stock + receipts_qty)` |
| `shortage_qty` | Integer | **Flow:** `demand_qty − fulfilled_qty` (lost, not back-ordered) |
| `closing_stock` | Integer | **Snapshot:** `opening_stock + receipts_qty − fulfilled_qty` |
| `on_order_qty` | Integer | **Snapshot:** quantity ordered but not yet received at week end |

Snapshot columns must not be summed across weeks. The report reads them for the selected (latest) week only.

### `fact_replenishment_orders`
| Column | Type | Description |
| --- | --- | --- |
| `order_id` | Text | `RO-00001` onward |
| `item_location_key` | Text | Foreign key to `dim_item_location` |
| `order_type` | Text | `Purchase` (raw materials) or `Production` (finished goods) |
| `order_date` | Date | Order date; the weekly planning run uses the last day of the week (one run on 4 Jan 2026 creates opening pipeline orders) |
| `expected_date` | Date | `order_date + planned_lead_time_days` |
| `order_qty` | Integer | Quantity ordered |
| `order_status` | Text | `Open` (no receipt yet), `Partially Received` (balance still due) or `Closed` (fully received), as of 5 Jul 2026 |

### `fact_order_receipts`
| Column | Type | Description |
| --- | --- | --- |
| `receipt_id` | Text | `RC-00001` onward |
| `order_id` | Text | Foreign key to `fact_replenishment_orders` |
| `receipt_date` | Date | Delivery date (always after the order date; receipts after 5 Jul 2026 are not recorded) |
| `received_qty` | Integer | Quantity received in this delivery |

An order with two deliveries has two receipt rows. There are no cancellations.

## 3. Reconciliation rules (enforced by `validate_data.py`)

| # | Rule |
| --- | --- |
| R1 | `closing_stock = opening_stock + receipts_qty − fulfilled_qty` |
| R2 | `fulfilled_qty = min(demand_qty, opening_stock + receipts_qty)` and `shortage_qty = demand_qty − fulfilled_qty` |
| R3 | `opening_stock` of week *t+1* equals `closing_stock` of week *t* |
| R4 | Weekly `receipts_qty` equals the sum of `fact_order_receipts.received_qty` for that item-location and week (exact) |
| R5 | Week-end `on_order_qty` equals cumulative `order_qty` (orders dated on or before week end) minus cumulative `received_qty` (receipts dated on or before week end) |
| R6 | Total received per order does not exceed `order_qty`; `order_status` matches the receipts |
| R7 | `receipt_date` is after `order_date`; `expected_date = order_date + planned_lead_time_days` |
| R8 | No negative quantities; no duplicate keys; no orphan foreign keys |

## 4. Generator design notes

- **Demand:** base weekly demand per item × seasonality × log-normal noise. Regional warehouses carry 30–60% of Pune's demand for the same item.
- **Seeded patterns** (deliberate, so the dashboard has exceptions to find): 3 item-locations with demand that stops partway or entirely; 6 slow-moving (intermittent) item-locations; 5 critical item-locations with a demand spike in weeks 18–23; 14 item-locations with ERP reorder points set below the policy level and 14 with ERP settings set well above it; 8 raw-material lanes with late-prone deliveries.
- **Simulated planner:** a stale static `(s, Q)` rule: when Inventory Position ≤ `erp_reorder_point_qty`, order enough multiples of `erp_order_qty` to exceed it.
- **Lead time:** planned lead time plus a random delay; 15% of raw-material orders and 7% of production orders are delivered in two parts.
- **Not in the data:** service-level targets, lead-time variance, forecast error, MOQ and pack size, transfers, backorders, cancellations.

## 5. Power BI-only objects

### Calculated table: `dim_date`
Daily calendar from 4 Jan 2026 to 5 Jul 2026 with `Year`, `Month`, `Month Sort`, `Week Start`, `Week Label`. Marked as the date table. Use `Week Start` for weekly axes.

### Calculated table: `dim_status`
Seven-row helper (Stocked Out, Critical Risk, Reorder Now, Excess, Slow-Moving, No Demand, Healthy) with a `Sort` column. Not related to any other table; used only to chart counts by status.

### Calculated table: `dim_doi_bucket`
Seven days-of-inventory buckets (0–7, 7–14, 14–21, 21–30, 30–45, 45–60, 60+ days) with `Lo`, `Hi` and `Sort`. Not related to any other table.

### What-If parameters
Defined in the model; the report pages use the default values and do not expose them as slicers.

| Parameter | Range | Default | Used for |
| --- | --- | --- | --- |
| `ADD Window` | 4–12 weeks | 8 | Average daily demand window |
| `Slow Lookback` | 4–12 weeks | 12 | Slow-moving look-back window (M) |
| `Slow Max Active` | 0–8 weeks | 4 | Slow-moving threshold (N): demand in ≤ N of the last M weeks |

### Calculated columns
| Table | Column | Definition |
| --- | --- | --- |
| `fact_replenishment_orders` | `First Receipt Date` | Earliest receipt date for the order |
| `fact_replenishment_orders` | `Received Qty` | Total quantity received against the order |
| `fact_replenishment_orders` | `Open Qty` | `order_qty − Received Qty` |
| `fact_replenishment_orders` | `Planned Lead Time` | `planned_lead_time_days` from `dim_item_location` |
| `fact_replenishment_orders` | `Actual Lead Time` | Days from `order_date` to `First Receipt Date`; blank if no receipt |
| `fact_replenishment_orders` | `Lead Time Variance` | `Actual Lead Time − Planned Lead Time`; blank if no receipt |
| `dim_item_location` | `Item Label` | `item_name \| city` (unique per item-location; used for drill-through) |
| `dim_item_location` | `Criticality` | `criticality` from `dim_item` |
